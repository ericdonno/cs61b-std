# 战斗系统说明

## 设计动机：从方向键到蓄力波

最早的战斗设计是"面朝某个方向按攻击键"——类似《以撒的结合》那种方向+攻击的经典模式。但实际体验下来有几个问题：

- **四方向攻击键占用了 F/R/C/V**，手要离开 WASD 区域，操作不流畅
- **单体攻击太弱**，被敌人包围时只能一个个打，缺少爽感
- **攻击没有节奏感**，只要能按就能打，缺乏策略深度

最终决定转向一个完全不同的设计：**蓄力范围攻击**。简单说就是——你不能随时出手，但一旦出手，周围一圈全部遭殃。

打个比方：这不是一把能连发的步枪，而是一枚需要充能才能引爆的炸弹。你得等能量条跑满，然后在合适的时机按下空格，释放一圈冲击波。

---

## 核心机制

### 蓄力条：你的"能量池"

蓄力条可以理解为一个自动充电的电池：

```
每帧自动恢复 2 点 → 满 100 点后可攻击 → 攻击后归零重新蓄力
```

| 参数 | 值 | 含义 |
|------|------|------|
| maxCharge | 100 | 最大能量 |
| chargeRate | 2 | 每帧恢复量 |
| 满蓄所需时间 | ~50 帧（约 0.8 秒 @ 60fps） | 两次攻击的最小间隔 |

**为什么设计为自动恢复而不是击杀充能？** 这样即使周围没有敌人，蓄力也会一直涨，鼓励玩家在战斗中保持移动、等待时机，而不是无脑前压。

### 范围攻击：一圈 8 格的冲击波

攻击判定覆盖玩家周围的全部 8 个格子：

```
   (x-1,y+1)  (x,y+1)  (x+1,y+1)
   (x-1,y)     @玩家    (x+1,y)
   (x-1,y-1)  (x,y-1)  (x+1,y-1)
```

每格独立判定伤害，所以被三个敌人围住时一次攻击就能同时命中三个。

### 伤害计算

```
伤害 = baseDamage + random(0, variance)
```

| 攻击方 | baseDamage | variance | 伤害范围 |
|--------|-----------|----------|----------|
| 玩家 | 15 | 5 | 15 ~ 20 |
| 敌人 | 10 | 3 | 10 ~ 13 |

方差的存在让每次攻击有轻微的随机浮动，避免"数学上能秒杀就一定秒杀"的确定性疲劳。

## 视觉反馈

### 攻击动画：橙色闪光

按下空格攻击时，玩家周围 8 格会短暂变成橙色 `*`（`ATTACK_FLASH` 瓦片），持续约 8 帧（~130ms）。视觉效果上像一圈爆炸冲击波从玩家位置向外扩散。

**为什么用"替换瓦片"而不是"改背景色"？** 这是刻意简化的选择。动态修改 TETile 的颜色需要侵入引擎层（TETile 的字段都是 private final），而 Tileset 中预定义瓦片完全不需要动引擎。牺牲了一点"原地变色"的精细度，换来了零侵入的实现——只加了一行 `ATTACK_FLASH` 常量。

### 受击反馈：玩家变红

玩家被敌人攻击时，人物符号 `@` 会变成红底，持续 8 帧。这只影响视觉，不影响游戏逻辑。类似于很多游戏中的"屏幕闪红"，让玩家清晰感知到自己在掉血。

## 玩家操作

| 按键 | 功能 |
|------|------|
| W / A / S / D | 上下左右移动 |
| 空格 | 蓄力满时释放范围攻击 |
| P | 暂停 / 继续 |
| : 然后 Q | 保存并退出 |

按空格时如果蓄力未满，不会消耗能量，终端会输出 `Charge not ready!` 提示。

## 架构说明

战斗系统通过三个模块协作完成：

```
Game.java（每帧循环）
  │
  ├─→ player.updateCharge()       每帧自动蓄力
  ├─→ 空格键 → attackPlayer()     检查蓄力 → 触发攻击
  │      │
  │      └─→ AttackAction.execute()
  │            │
  │            ├─ resetCharge()    立即消耗蓄力（无论是否命中）
  │            ├─ 遍历周围8格 → calculateDamage() → dealDamage()
  │            └─ setHitTimer(8)   设置受击闪烁
  │
  ├─→ enemy.updateAI()            敌人 AI（相邻时攻击玩家）
  │
  └─→ buildActiveFrame()
       ├─ getDisplayTile()         受击时返回红色 PLAYER_HIT
       └─ 攻击动画帧内替换 ATTACK_FLASH
```

**关键设计决策：蓄力在检测伤害之前消耗。** 即使周围一个敌人都没有，按空格也会清空蓄力条。这避免了"试探性按空格看有没有敌人"的 meta 玩法——每次出手都是真正的决策。

## 参数调整指南

| 参数 | 位置 | 效果 |
|------|------|------|
| `chargeRate` | Player.java | 调大 = 攻击更频繁，游戏更简单 |
| `maxCharge` | Player.java | 调大 = 蓄力更慢，考验耐心 |
| `attackDamage` / `variance` | Player.java | 玩家输出，调高 = 敌人死更快 |
| `enemy.hp` | Enemy 构造函数 | 调高 = 敌人更肉，需要更多次攻击 |
| 动画帧数 (8) | Game.java `buildActiveFrame()` | 调大 = 动画更持久 |

所有参数都是硬编码的常量，修改后重新编译即可生效。
