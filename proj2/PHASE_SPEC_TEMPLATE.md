# DungeonMind Phase Spec 模板

> 用途：为单个开发阶段生成可实施、可审查、可交接的构筑契约。
>
> 禁止仅根据 Roadmap 的阶段标题填空。生成者必须先完成仓库审计，并以当前代码、测试和上一阶段证据为依据。

- 作者与审查者：
- 创建日期：

- 前一阶段 Completion：
- 适用 Intent / Roadmap 版本：

## 1. 必读输入与审计范围

列出生成本 Spec 时实际读取的文件、代码模块、测试、运行记录和官方技术文档。必须包括：

- `PROJECT_INTENT_zh-CN.md`
- `DEVELOPMENT_ROADMAP.md`
- 上一阶段 `PHASE_N_COMPLETION.md`（Phase 0 除外）
- 与本阶段有关的当前代码和测试
- 易变化依赖的当前官方文档

没有读取的内容不得暗示已经确认。

## 2. 阶段目标与成功定义

用一段话说明本阶段结束后，系统新增了什么可运行能力。说明它怎样推动 Agent MVP，而不是只列框架名称。

## 3. 起始事实

记录审计确认的当前事实，并附文件与行号。至少覆盖：

- 已有能力；
- 可复用接口；
- 当前失败或技术债；
- 测试与运行入口；
- 与 Roadmap 假设不一致的地方。

将“事实”“推断”“建议”分开表述。

## 6. 已锁定决定、假设与待决定项

### 已锁定决定

记录本阶段不得由实现者随意改变的接口、边界、命名或行为。

### 暂时假设

记录为推进工作所作、但可被证据推翻的假设及验证方式。

### 需要 Builder 决定

只放会改变产品体验、学习目标或跨阶段契约的问题。每项说明选项、影响和 Advisor 建议。

## 7. 目标架构与数据流

描述本阶段新增或改变的数据所有权、调用方向和生命周期。必要时画最小流程图。

必须回答：

- 谁创建数据？
- 谁可以读取和修改？
- 如何关联请求、决策、动作和结果？
- 失败、取消或过期时发生什么？
- 哪些数据会保存，何时清理？

## 8. 接口与数据契约

给出本阶段需要实现的确切类、方法、schema、枚举和关键不变量。示例必须能与当前语言和依赖版本对应。

对于跨进程或持久化格式，必须包含：

- schema/version 字段；
- 必填与可选字段；
- 身份与关联字段；
- 校验失败行为；
- 向后兼容策略。

## 9. 逐文件变更计划

| 文件 | 新建/修改 | 责任 | 关键变更 | 不应包含 |
|------|-----------|------|----------|----------|
| | | | | |

禁止使用“修改相关文件”这类无法执行的描述。

## 10. 实施顺序

将工作拆成能够单独编译、测试和审查的小步。每一步写明：

1. 输入；
2. 具体改动；
3. 验证命令；
4. 通过后产生的 artifact。

## 11. 测试与验收矩阵

| Test ID | 场景 | 断言 | 自动/人工 | 对应需求 |
|---------|------|------|-----------|----------|
| | | | | |

测试必须覆盖正常路径、边界、失败路径和“不应发生”的行为。对随机或 LLM 行为，区分 deterministic contract test 与统计/人工评估。

## 12. Observability 与运行证据

规定本阶段必须记录的 trace、日志、指标和关联字段。说明哪些字段属于 deterministic canonical evidence，哪些只是诊断信息。

不得把自由文本 reasoning 当作唯一验收证据。

## 13. 失败处理、兼容与迁移

说明：

- 新能力不可用时如何退化；
- 旧存档、旧配置或旧接口如何处理；
- 是否需要 feature flag；
- 如何避免半完成状态污染后续阶段；
- 哪些行为有意保持为 legacy baseline。

## 14. 风险与停止条件

列出最可能导致返工、作弊、不可测、性能问题或玩法误判的风险。

如果发现需要突破 Intent、Roadmap 或扩大 Phase 范围，停止实现并回到 Specification/Decision，而不是自行扩张。

## 15. Definition of Done

用可证伪的 checklist 表达。至少包括：

- [ ] 所有 In Scope 交付物存在。
- [ ] 指定自动化测试通过。
- [ ] 固定场景或人工验收通过。
- [ ] 没有违反对应 INV 约束。
- [ ] 运行命令与结果已记录。
- [ ] 已知失败和偏差没有被隐藏。
- [ ] `PHASE_N_COMPLETION.md` 已生成。
- [ ] 下一阶段所需 artifacts 已明确交付。

## 16. 下一阶段交接

明确列出下一阶段可以依赖的：

- 稳定接口与 schema；
- 测试 fixture 与命令；
- trace 或 baseline artifact；
- 已确认设计决定；
- 未解决问题和禁止假设的事项。
